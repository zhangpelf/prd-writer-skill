# PRD 自动化撰写与流转协同工作流 v2.1

## 概述

这是一个专为**中后台、小程序、App 与各类型产品研发场景**设计的专业级 PRD（产品需求文档）工作流，具备**零额外商业 API 费用、双场景智能适配、历史文档自动合并更新、本地双重持久化以及多端协同通知**等核心能力：

1. **AI 撰写技能（Skill）**：在 AI 智能体 / Claude Code 环境中运行，一键输出符合通用研发规范（结构化七大章节、Given/When/Then 验收标准、组件类型明确标注、通用安全脱敏要求）的高质量 PRD 正文。
2. **本地双重持久化**：主路径（项目 `docs/` 目录）与备份路径（`~/Downloads/prd-reports/`）双保险自动保存。
3. **多端协同与编排（Webhook / n8n）**：原生支持将 PRD 摘要与卡片推送至 **飞书（Feishu）**、**企业微信（WeCom）**、**钉钉（DingTalk）** 或邮箱，并可选由 n8n 自动化归档至团队知识库或本地存储。

## 七大核心章节标准

| 章节 | 核心内容 | 研发与业务价值 |
|------|---------|---------------|
| **版本历史** | 版本号、修订时间、作者、变更标识（新建/迭代）、变更说明、审核人 | 保障需求迭代历史可追溯，合并更新时严格追加保留历史版本 |
| **1. 概述** | 规范一句话描述（为解决...本次建设...从而实现...）、业务背景、目标用户画像、量化 KPI（基线→目标+计算公式） | 团队统一认知，明确产品目标衡量标尺 |
| **2. 功能需求** | 用户动线表、Mermaid 业务流程图、术语字典、P0/P1/P2 功能分级、Given/When/Then 验收标准、页面详述（组件规范） | 研发核心开发依据，原型与组件类型标注极大提升前端代码开发精度 |
| **3. 非功能需求** | P95/P99 响应耗时、并发能力、敏感信息脱敏、审计日志留存 180 天、HTTPS 加密、浏览器兼容 | 架构设计、安全与运维把关基线 |
| **4. 数据模型与接口** | 核心实体抽象定义、RESTful 风格 API 路由、标准响应结构 `{code, message, data}`、错误码定义 | 前后端联调契约，降低接口对齐沟通成本 |
| **5. 发布计划** | 里程碑阶段周期、关键交付物、责任人、依赖项、v1.0 (MVP) → v1.1 → v2.0 版本演进规划 | 项目排期与交付管控蓝本 |
| **6. 风险评估** | 风险发生概率×影响程度矩阵、成因、预防与应急处置预案、责任人 | 提前暴露技术与业务风险，规避上线故障 |

## 快速开始与安装指南

### 1. 本地 Skills 架构部署

本项目遵循本地 Skills 规范体系：
- **主维护源**：`.agents/skills/prd-writer/`
- **项目兼容目录**：`skills/prd-writer/`
- **工作流专属目录**：`n8n-workflows/prd-writer-skill/`

已在 `.agents/SKILLS_REGISTRY.md` 完成注册登记。

### 2. 配置文件说明（`config/prd-config.yaml`）

编辑 `config/prd-config.yaml`：

```yaml
prd_writer:
  local_output_dir: "{project_root}/docs"         # 本地主保存目录
  local_backup_dir: "~/Downloads/prd-reports"        # 本地备份绝对路径
  title_prefix: "【PRD】"                         # 文档文件名前缀
  auto_save_local: true                           # 强制自动保存到本地

  # 协作推送配置
  auto_publish: false                             # 设为 true 自动发送 Webhook
  webhook_url: ""                                 # 飞书/企微/钉钉机器人或 n8n Webhook
  notify_type: "feishu"                           # feishu | wecom | dingtalk | email | none
  notify_target: ""                               # 目标标识

  design_system: "Ant Design"                     # 推荐组件库: Ant Design | Element Plus | TDesign
  compliance_preset: "standard"                   # 安全预设: standard
```

### 3. 触发与使用

在对话中直接输入：
- `/prd-writer`
- `帮我写一份 PRD`
- `生成需求文档`
- `撰写产品需求文档`

## 常见问题 (FAQ)

**Q: 为什么不用单一的 Markdown 增量补丁，而要全量合并更新？**  
A: 增量补丁在跨部门交付与研发实现时极易产生理解偏差。全量合并更新确保任何时候从主路径拿出来的都是最新、自洽、开箱即用的唯一权威版本。

**Q: Webhook 推送失败会导致本地生成的 PRD 丢失吗？**  
A: 绝对不会。本工作流严格执行**防阻断降级策略**，本地保存与对话渲染先于远程推送执行。Webhook 任何网络波动、地址无效或权限问题仅会在回执中标记为“降级跳过”，绝不影响本地文件落盘。
