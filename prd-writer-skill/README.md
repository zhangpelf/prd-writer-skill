# PRD 自动化撰写与流转协同工作流 v2.1

> 零额外 API 费用 · 双场景智能适配 · 历史文档自动合并 · 本地双重持久化 · 多端协同通知

## 概述

专为**中后台、小程序、App 与各类型产品研发场景**设计的专业级 PRD（产品需求文档）自动化工作流。在 AI 智能体环境中运行，一键输出结构化七大章节、Given/When/Then 验收标准、主流组件类型标注的高质量 PRD 正文，并自动完成本地持久化与多端协同推送。

---

## 核心特性

| 功能模块 | 说明 |
|---------|------|
| **双场景智能适配** | 自动识别**迭代场景**（四列差异对比表）与**新增场景**（两列全貌动线表），精准匹配 PRD 表达结构 |
| **历史 PRD 检测与合并更新** | 自动扫描 `docs/` 与备份目录，检测同域历史 PRD，支持全量合并更新（严禁增量 diff），版本历史自动追加 |
| **标准化七大章节** | 版本历史 → 概述 → 功能需求 → 非功能需求 → 数据模型与接口 → 发布计划 → 风险评估，缺一不可 |
| **本地双重持久化** | 主路径（项目 `docs/`）与备份路径（`~/Downloads/prd-reports/`）双保险自动保存 |
| **多端协同推送** | 原生支持 **飞书**（交互卡片）、**企业微信**（Markdown）、**钉钉**（Markdown）、邮件及 n8n 网关，推送失败安全降级 |
| **主流组件库映射** | 标准化标注组件类型（Cascader、TreeSelect、Upload、DatePicker、Drawer、Popconfirm 等），对齐 Ant Design / Element Plus / TDesign |
| **通用安全规范** | 敏感字段脱敏显示、核心操作审计留存 ≥180 天、HTTPS 加密、内容安全审核 |

## 执行流水线

完整流水线必须按序执行，不得跳步：

```
Step 0  历史 PRD 检测（新建 or 合并更新模式判定）
  │
Step 1  场景识别（迭代 / 新增）
  │
Step 2  信息收集（业务背景、功能范围、安全约束、KPI）
  │
Step 3  七大章节 PRD 生成
  │
Step 5  对话窗口渲染完整正文  ─── 场景一验收 ✓
  │
Step 6  本地双路径保存          ─── 场景二验收 ✓
  │      ├── 主路径: {project_root}/docs/【PRD】{名称}.md
  │      └── 备份:   ~/Downloads/prd-reports/
  │
Step 7  Webhook 协同推送        ─── 场景三验收 ✓
  │      └── 飞书 / 企微 / 钉钉 / 邮件 / n8n（未配置或失败则安全降级）
  │
Step 8  三场景验收回执输出
```

## 七大核心章节

| 章节 | 核心内容 | 研发与业务价值 |
|------|---------|---------------|
| **版本历史** | 版本号、修订时间、作者、变更标识、变更说明、审核人 | 迭代可追溯，合并更新时严格追加保留历史 |
| **1. 概述** | 一句话描述（为解决…本次建设…从而实现…）、业务痛点、用户画像、量化 KPI | 统一团队认知，明确目标衡量标尺 |
| **2. 功能需求** | 用户动线表、Mermaid 流程图、术语字典、P0/P1/P2 分级、Given/When/Then 验收、页面详述 | 研发核心开发依据，组件标注提升前端精度 |
| **3. 非功能需求** | P95/P99 响应耗时、并发能力、脱敏规范、审计日志、HTTPS、浏览器兼容 | 架构与安全基线 |
| **4. 数据模型与接口** | 核心实体、RESTful API、标准响应 `{code, message, data}`、错误码 | 前后端联调契约 |
| **5. 发布计划** | 里程碑阶段、交付物、依赖项、MVP → 迭代版本演进 | 排期与交付管控 |
| **6. 风险评估** | 概率×影响矩阵、成因、预防与应急预案、责任人 | 提前暴露风险，规避上线故障 |

## 快速开始

### 1. 安装

将本 skill 放入 AI 智能体的 skills 目录：

```bash
# 方式一：直接克隆
git clone https://github.com/zhangpelf/prd-writer-skill.git

# 方式二：作为 skill 目录部署
cp -r prd-writer-skill/ .agents/skills/prd-writer/
```

### 2. 配置（`config/prd-config.yaml`）

```yaml
prd_writer:
  # 本地存储
  local_output_dir: "{project_root}/docs"       # 主保存目录
  local_backup_dir: "~/Downloads/prd-reports"    # 备份路径
  title_prefix: "【PRD】"                       # 文件名前缀
  auto_save_local: true                         # 强制自动落盘

  # 协同推送（可选）
  auto_publish: false                           # 设为 true 启用 Webhook
  webhook_url: ""                               # 飞书/企微/钉钉机器人或 n8n 网关地址
  notify_type: "feishu"                         # feishu | wecom | dingtalk | email | none
  notify_target: ""                             # 目标标识

  # 规范偏好
  design_system: "Ant Design"                   # Ant Design | Element Plus | TDesign
  compliance_preset: "standard"                 # 安全预设
```

### 3. 触发使用

在对话中直接输入：

- `/prd-writer`
- `帮我写一份 PRD`
- `生成需求文档`
- `撰写产品需求文档`

## 合并更新策略

进入合并更新模式时的强制规则：

1. **先完整读取历史 PRD** → 以历史版本为基础蓝本
2. **严禁输出增量 diff** → 最终交付必须是完整、自洽、可直接交付研发的全量 PRD
3. **版本历史追加** → 追加新版本行，保留全部历史记录
4. **全章节合并**：概述取并集、功能需求追加并重新分级、非功能需求合并补充、数据模型追加字段与接口、发布计划追加里程碑、风险评估追加新风险

## 三场景验收回执

每次生成完毕，末尾输出验收表：

| 场景 | 验收规范 | 状态 | 凭证 |
|------|---------|------|------|
| **场景一** | 对话窗口渲染完整 PRD 正文 | ✅/❌ | PRD 正文已在对话输出 |
| **场景二** | 自动落盘（主路径 + 备份路径） | ✅/❌ | 主路径 + 备份路径 |
| **场景三** | Webhook 协同通知 | ✅/⚠️降级/❌ | 推送状态或降级原因 |

- 场景一、二任一失败 → 流程阻断，给出补救指引
- 场景三未配置或失败 → 安全降级，不阻断主任务

## FAQ

**Q: 为什么不用增量补丁，而要全量合并更新？**
A: 增量补丁在跨团队交付时极易产生理解偏差。全量合并确保任何时候从主路径拿出来的都是最新、自洽、开箱即用的唯一权威版本。

**Q: Webhook 推送失败会导致本地 PRD 丢失吗？**
A: 不会。本工作流执行**防阻断降级策略**，本地保存先于远程推送。Webhook 任何网络问题仅在回执中标记"降级跳过"，不影响本地文件落盘。

**Q: 支持哪些 AI 智能体环境？**
A: 任何支持 Skill/Agent 规范的环境均可使用，包括 Claude Code、OpenCode、Antigravity 等。将 `SKILL.md` 放入对应 skills 目录即可。
